# Publishing the Media Bridge Repository

This project is designed to keep source code and large release artifacts
separate.

## Repository

The public source repository is
[`cell-beep/media-bridge`](https://github.com/cell-beep/media-bridge). It
contains `LICENSE`, documentation, tests, and build scripts. Files ignored by
`.gitignore`--especially browser profiles, signing keys, `.env` files,
generated `dist` directories, and installers--must not be committed.

The maintainer account must keep GitHub two-factor authentication enabled.

Publication and later synchronization from the prepared Windows workspace can
be performed with `scripts/publish-first-github.ps1`. It stages only files
allowed by `.gitignore`, creates a commit when needed, configures `origin`, and
pushes the `main` branch. Later runs can pass a descriptive message with
`-CommitMessage 'Describe the change'`.

## GitHub Pages

Publish the contents generated by `scripts/prepare-public-site.ps1` from a
dedicated Pages branch or a Pages deployment workflow. The resulting stable
HTTPS URLs should be used for the product page, privacy policy, support page,
third-party notices, and Firefox reviewer test media.

## GitHub Releases

Attach these generated files to a tagged release instead of committing them:

- the signed Helper installer;
- SHA-256 checksum files;
- the complete dependency license bundle;
- any corresponding-source archive required by the bundled FFmpeg build.

The extension ZIP is submitted to browser stores. It may also be attached to a
release for auditability, but the store remains the normal installation path.

Do not publish an unsigned installer as a production release. A draft or
clearly marked prerelease may be used for reviewer coordination only when its
unsigned status is unmistakable.
